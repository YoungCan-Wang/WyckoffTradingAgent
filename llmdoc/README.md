# LLM 决策文档

`llmdoc/` 保存需要进入交易 LLM 上下文、同时又必须接受 Git 审查的决策注释。它不是行情库、用户持仓库或参数配置中心。

## 应该放什么

- 长期决策纪律：例如 `EXIT`、`TRIM`、尾仓和硬止损的边界。
- 已复盘案例：记录当时可见证据、判断失误、可推广教训和不能推广的部分。
- 明确的适用范围：`step4`、`holding_diagnosis` 等工作流，以及可选的股票代码。
- 失效或复核日期：事件型个股注释必须设置 `expires_on`，避免陈旧题材永久影响判断。

## 不应该放什么

- 当前价格、仓位、成本和盘中消息；这些必须来自实时数据与持仓表。
- 用户个人偏好；多用户环境下应进入按用户隔离的设置或 Agent 记忆。
- 未经回测的阈值修改、买卖指令或绕过 OMS 的白名单。
- API Key、数据库导出、聊天原文和无法追溯的传闻。

## 运行边界

`index.json` 是装载清单。运行时按照工作流、股票代码和有效期选择文档，并限制总字符数。文档只作为咨询性上下文：硬止损、市场闸门、确定性候选准入和 OMS 始终优先。一次错过涨停只能形成案例，不能直接晋级为生产规则。

该目录同时作为 Python package data 发布，保证源码运行、GitHub Actions 和 wheel 安装使用同一份文档；新增子目录或文件类型时必须同步检查 `pyproject.toml` 的 package-data 清单。
