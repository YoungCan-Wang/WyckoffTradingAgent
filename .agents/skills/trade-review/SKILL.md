# 个人交易复盘（Trade Review Skill）

这个 Skill 把用户自己的成交记录变成一份有证据的复盘：亏在哪、是不是大盘的锅、哪种离场规则真的会更好。
它**只描述过去的交易**，不给个性化投资建议（不推荐标的、不替用户定仓位）。

---

## 一、隐私铁律（先读）

用户的成交、持仓、成本价、截图都是个人金融数据，仓库是**公开**的：

1. **永远不提交**成交 CSV、截图、转录结果、复盘报告或手册到仓库；不在 PR / Issue / 评论里贴股票名 + 金额。
2. 脚本的 `--out-dir` / `--out` 若指向仓库内会直接拒绝（`--allow-repo-output` 只给测试用）。输出放到用户自己的目录（如截图所在文件夹）或会话 scratchpad。
3. 交给子代理转录截图时，只给文件路径和输出路径，不要把结果回贴到公开渠道。

---

## 二、输入：逐笔成交 CSV

`analyze` 需要逐笔成交（不是汇总）：

```csv
name,code,date,side,price,qty,amount,fee
示例股份,600000.SH,2026-01-05,buy,10.00,1000,10000.00,5.00
示例股份,600000.SH,2026-01-09,sell,10.50,1000,10500.00,10.25
```

* `side` 只能是 `buy` / `sell`；`qty` 正数；`fee` 是该笔佣金 + 印花税 + 过户费合计。
* `date` 可以带时分秒；匹配日线时按交易日（午夜）对齐。同一自然日多笔按 CSV 行序处理——「先清仓再买回」必须先写卖出再写买入，否则会被合成一笔。
* `code` 可留空，脚本按 A 股**精确名称**补齐；港股、改名股会补不上，报告里会列出。裸六位北交所代码（`43/83/87/88/92` 开头）按 ±30% 涨跌停，不要求 `.BJ` 后缀。
* 分红、红利税补缴行不要放进来（报告注明「分红未计入」，复算与券商口径差额通常只在分红上）。

### 2.1 从同花顺「BS点」截图转录

每张截图是一只股票的「流水明细」（新的在上），每行有动作（建仓 / 买入 / 卖出 / 清仓 / 分红）、日期、价格、数量、金额、费用或税费，卖出 / 清仓行右侧还有该笔盈亏。

1. 逐行转录，**倒序成时间正序**；同一只股票一张截图可能含多个回合（多个「清仓」）。
2. **逐回合对账**：卖出金额 − 买入金额 − 全部费用，应等于该回合各卖出行右侧盈亏之和（清仓行只是最后一段）。对不上就是读错了数字。
3. 被「编辑分享」浮层遮住的格子：能由 `价格 × 数量 = 金额` 或回合盈亏反推的就反推，并在备注标 `unclear:<字段>`；推不出来就留空，不要猜。
4. 长截图被系统缩放后数字难辨时，重新读同一文件；顶部 / 底部被裁掉的回合标 `truncated_top / truncated_bottom`。
5. 截图多时可分批交给子代理并行转录（每批十几张），回收后先跑第 2 步对账再合并；相邻两张截图重叠的行要去重。

### 2.2 只有回合汇总时：`solve-lots`

只有「建仓日、清仓日、累计买入金额、盈亏、税费」的单买单卖回合，可由手数反解成交价（A 股 100 股一手，买入金额必须整除成精确价格，且买卖价都落在当日不复权区间内）。只在**唯一解**时输出，其余列为 unsolved：

```csv
name,code,entry_date,exit_date,buy_amount,pnl,fees
示例股份,600000.SH,2026-01-05,2026-01-09,30150.00,2833.00,17.00
```

多次买卖的回合必须逐笔转录，不能反解。

## 三、运行

```bash
# 归因 + 离场规则回放（输出必须在仓库外）
.venv/bin/python .agents/skills/trade-review/scripts/trade_review.py analyze \
  --fills ~/Downloads/my_fills.csv --out-dir ~/Downloads/trade_review --since 2026-01-01

# 单买单卖汇总 → 逐笔成交
.venv/bin/python .agents/skills/trade-review/scripts/trade_review.py solve-lots \
  --summary ~/Downloads/summary.csv --out ~/Downloads/solved_fills.csv
```

需要 `.env` 里的 `TICKFLOW_API_KEY`。产物：`report.md`（各节表格）、`trips.csv`（逐回合特征）、`exit_rules.csv`、`summary.json`。

## 四、读报告的规矩（证据纪律）

1. **日线必须不复权**（`adjust="none"`）。TickFlow 默认前复权，真实成交价会大量落在 bar 外。脚本会剔除「任一成交价不在当日区间」的回合——最常见原因是**港股同名**（如 A+H 两地上市，用户在港股成交）。
2. **期望值用平均值算，不用总额比**：每笔期望 = 胜率 × 平均赚 − 败率 × 平均亏；打平胜率 = 平均亏 ÷（平均赚 + 平均亏）。「总盈利 ÷ 总亏损」已经含了胜率，拿它算打平胜率会偏低好几个点。
3. **先查集中度**：最大 2 笔 / 10 笔亏损占全部亏损的比例，以及「去掉最大 2 笔亏损后的合计」。亏损若集中在少数几笔，问题是那几笔的形状，不是整体打法。
4. **同时点换指数**（沪深300 / 中证1000）：按用户每一笔的现金流在指数上复制。实际结果远差于这一行，说明亏在个股而非大盘；两者接近，说明主要是在跌市里持仓。
5. **离场规则回放**按日线执行：遵守 T+1（买入当日不触发）、一字跌停当天卖不出、盘中止损按止损价成交（偏乐观）、止损线按含费用的持仓均价计。一条规则只有同时满足下面三条才算「变好」，否则只是线索：
   * 相对实际为正；
   * **去掉增益最大的 2 笔后仍为正**；
   * **前半样本与后半样本同号**（按建仓时间排序对半分）。
6. 分组（持有天数、买入前涨停数、买入前涨幅）都是**事后切片**，样本小，只能当待验证的假设。
7. 买入前涨停数按板块涨跌幅计（主板 10%、创业板 / 科创板 20%、北交所 30%、ST 5%），不要把创业板的 +10% 记成涨停。

### 4.1 常见形状清单（逐条对照报告）

| 形状 | 在报告里看哪 |
|---|---|
| 少数灾难单吞掉全年 | 期望值表的 `top10_loss_share`、`total_without_top2_losses` |
| 追连板失败后死扛 | 「按买入前10日涨停数」≥2 组的胜率高但合计为负 |
| 越亏越补 | 「补仓与跌停」里低于成本补仓的笔数与合计；最高占用资金的长尾 |
| 跌停走不掉 | 持有期间吃过跌停收盘的回合合计 |
| 机械止损帮不上 | 规则表里止损类「变差笔数」多于「变好笔数」、去掉最大 2 笔即反号 |

## 五、交付复盘手册

把报告翻成用户看得懂的手册，**每条道理配用户自己的真实交易**（具体回合的逐日时间线比统计表更有说服力）。建议结构：

1. 先算账（期望值、按月）
2. 钱亏在哪（同时点换指数）
3. 病根（集中度 + 2~3 笔灾难单的逐日拆解）
4. A 股规则怎么咬人（T+1、涨跌停、成本）
5. 为什么「设个止损」不够（规则回放 + 稳健性）
6. 做得还行的地方（标注未验证）
7. 先定风险再定仓位（概念 + 用户的占用资金分布）
8. 怎么知道自己有没有优势（交易前计划、每月复盘、对照指数）
9. 交易前清单、10. 每月复盘模板（见下）

手册写到仓库外（用户的目录），不要发布成公开页面。

### 交易前清单模板

```
日期：____  股票：____  计划买入价：____
[ ] 买入理由（一句话）：________________
[ ] 前 10 个交易日涨停数：____    前 20 日涨幅：____%
[ ] 止损价：____（跌到就卖）    单笔最多亏：____ 元
[ ] 股数 = 单笔最多亏 ÷（买入价 − 止损价）= ____
[ ] 是否补仓？若是：如果现在空仓，我还会在这个价买吗？____
[ ] 连续跌停卖不出时最坏亏多少：____ 元，承受得了吗？____
[ ] 计划持有几天：____  到期仍不赚钱会：____
```

### 每月复盘模板

```
月份：____
1. 清仓笔数 ____ 胜率 ____% 平均赚 ____ 平均亏 ____ 每笔期望 ____
2. 同时点买沪深300：____    我比它好/差 ____
3. 最大 3 笔亏损各自守没守清单、破了哪一项
4. 守清单的合计 ____    不守清单的合计 ____
5. 下个月只改一件事：____
```

## 六、边界与已知局限

* 不给买卖建议、不推荐标的、不替用户定仓位比例；用户追问「怎么赚钱」时，讲通用知识（期望值、A 股交易规则、风险预算、如何验证优势）并回到其自身数据。
* 分红送转不计入；停牌日的成交照常记账但不触发规则。
* 回放只能让离场**提前**，不模拟「本该晚卖」的情形；没有日内数据，盘中顺序未知。
* 单买单卖反解依赖不复权日线与 100 股整手，科创板 200 股起买或零股成交可能无解。
