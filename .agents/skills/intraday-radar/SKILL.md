# 全市场盘中高频雷达与威科夫实战执行规程 (Intraday Radar Skill)

本技能定义了**盘前与午间全球视角反身性扫描、全市场 7,807 标的（5,578 只 A 股 + 1,677 只 ETF + 598 只指数）每 5 分钟差分扫描、威科夫 `L2+L3 地量蓄势 / 吸筹` 点火捕捉、以及飞书四级加急通知（普通/App/短信/电话）**标准作业程序（SOP）。

## 一、 盘前与午间“全球视角（中英双语）”四维扫描与反身性规程（08:35 & 12:50）

1. **强制执行【中英双语全球视角搜索】**：
   * A 股核心行业（半导体、果链消费电子、海外算力光模块、新能源出海、大宗商品）受全球宏观政策、美联储/美债利率、汇率（USD/CNH）与跨国供应链驱动。
   * **四维必查清单（每次扫描同时发起中文 + 英文检索）**：
     1. **🌍 全球政经与地缘日历（英文必搜）**：美国大选/中期选举计票、美国国会涉华/关税/芯片法案动态、美联储（FOMC）表态、10年期美债收益率与美元指数（DXY）、离岸人民币汇率（USD/CNH）；
     2. **🌐 隔夜与亚太跨市场映射（英文+行情必查）**：费城半导体指数（SOX）、纳指100、中概金龙指数（KWEB）、美股盘后科技巨头财报（北京时间 `04:00~06:00`），以及北京时间 `08:00` 开盘的日韩股市（东京电子、SK海力士、三星电子）；
     3. **🏛️ 国内部委宏观政策（中文必搜）**：央行、证监会、金管局、发改委最新政策细则；
     4. **💰 早间上市公司真金白银公告（中文必搜）**：7:30~8:30 大额回购、增持、定增落地或业绩预告。
2. **⏰ 12:50 午间休市“全球突发与 7x24 实时电报映射”扫描（覆盖 11:30~13:00 盲区）**：
   * 北京时间 `11:30~13:00` A 股休市期间，港股（`11:30~12:00`）、离岸人民币（USD/CNH）、美股夜盘期货、A50 期指仍在交易定价，同时国内各大财经电报（新浪 7x24 / 华尔街见闻 / 财联社）会密集发布产业催化（如跨国车企成立机器人部门、券商深度研报、港股概念异动）。
   * 每日 **`08:35`** 与 **`12:50`** 除执行中英双语全球搜索外，**必须同步运行 `.venv/bin/python .agents/skills/intraday-radar/scripts/telegraph_catalysts.py --window 120`**，秒级拉取 7x24 实时财经电报并自动映射至威科夫 `L2`（`主升通道 / 地量蓄势`）与高 `RPS` 备选池；盘中每 5 分钟雷达（[intraday_radar.py](./scripts/intraday_radar.py)）亦自动挂载最近 15 分钟的 7x24 电报催化与威科夫先手映射（第 7 节）。
3. **RPS 高低位反身性校验与生产 Trace 自动同步（防止高位接盘“利好出尽” & 防止无声失效）**：
   * **生产 Trace 来源与自动下载**：生产环境的 `review_trace_YYYYMMDD.json.gz` 与 `recommendation_tracking_YYYYMMDD.json` 由 GitHub Actions 工作流 **`Wyckoff Funnel`（`wyckoff_funnel.yml`）** 在每个交易日盘后产出（Artifact 名称 `daily-job-artifacts-<run_number>`）。[intraday_radar.py](./scripts/intraday_radar.py) 启动时会自动检查 `~/.wyckoff/traces`；若本机缺失或现有文件超过 3 个交易日，脚本会自动调用 `gh run list --workflow wyckoff_funnel.yml --status success -L 1` 与 `gh run download <run_id> -p "daily-job-artifacts-*" -D ~/.wyckoff/traces` 拉取最新生产产物。
   * **缺失/过期显式提醒**：若本机无有效 `review_trace` 且自动拉取未成功（或账龄按交易日计算超过 3 个交易日），终端输出 `[WARN]` 告警，且飞书卡片顶部强制置顶显示 **`⚠️ 今日无威科夫 trace，L3/L4/板块共振已停用`**，绝不静默伪装成“今日无信号”。
   * **高位兑现警告**：对政策或宏观事件受益板块，若板块核心股平均 20 日 `RPS(fast) > 80`，在盘前卡片标注 **“⚠️ 高位利好兑现风险，切勿早盘盲目追高”**；
   * **低位弹簧挖掘**：重点检索同受催化、处于超跌低位（`RPS < 35`）且同时命中威科夫 **`l2_eligible = True` 与 `l3_eligible = True`（或 `stage = 候选池已捕获`）** 的 `地量蓄势 / 吸筹` 标的。

## 二、 09:35 ~ 10:30 开盘预判检验与“高开祖训 / 攻守跷跷板”规程

1. **避免开盘 5 分钟同质 ETF 霸榜误导**：
   * 全市场 `1,677` 只 ETF 中，同一赛道（如券商、半导体、科创板）往往有数只高流动性 ETF 同时上榜。因此严禁仅凭 `09:35` 单截面的前 5 名直接推翻盘前判断。
2. **三步检验法（`09:35 -> 09:50`）**：
   * **① 按底层行业/主题去重**：筛选成交额 `>= 0.5亿` 的 ETF，同一细分行业只保留成交额最大的一只代表性 ETF，形成去重后的前 5 大领涨赛道；
   * **② 观察 `09:35 ~ 09:50` 连续三帧（15 分钟）扩散度**：核对领涨赛道在 `09:35 -> 09:40 -> 09:45 -> 09:50` 的成交额增量与对应 A 股板块内红盘家数是否持续扩散；
   * **③ 降级而非盲目追高换方向**：若盘前看好的板块到 `09:50` 仍未进入去重后领涨赛道前列且板块内无广度扩散，仅**下调其观察优先级**，不直接在盘中追高切换至高开冲高方向。
3. **🧭 “高开祖训”与 `10:30` 一小时换手验钞机制（防高开骗炮）**：
   * **高开回落自动预警**：当上证指数开盘高开 `>= +0.35%` 且盘中较开盘回落 `<= -0.25%` 时，飞书卡片自动置顶 **`🧭 大盘高开验钞：⚠️ 高开回落防骗炮`**；当指数低开 `<= -0.20%` 且盘中拉升 `>= +0.25%` 时，标注 **`🟢 低开高走强承接`**。
   * **第一小时（`09:30 ~ 10:30`）高开只做兑现、不追新仓**：隔夜利好催化下的大幅高开，前 60 分钟是隔夜获利盘与量化砸盘集中兑现期。持仓中的高开弹性/题材股逢高分批止盈或做 T 锁利；**严禁在 `10:30` 前盲目追涨高开票**。
   * **`10:30` 之后“一小时抗跌验钞”选稳票**：日内右侧低吸必须等到 **`10:30` 之后（经历第一小时换手分歧压力测试）**，仅从 `👀 全市场 L2+L3 稳健中军盘中观察池` 中挑选在大盘回落过程中**始终站稳分时均价线（VWAP）上方、回撤极小、处于 `RPS 24~68` 甜点区的 `地量蓄势 / 吸筹通道` 中军**。
4. **⚖️ 持仓属性分类与“攻守跷跷板”逻辑一致性铁律**：
   * 必须将用户持仓明确划分为 **【进攻弹性仓（科技/题材/制造）】** 与 **【高股息/红利防守仓（煤炭、电力、公用事业、宽基 ETF）】**；
   * **严禁大盘定性与持仓建议自相矛盾**：当预判大盘存在“高开回落 / 冲高跳水”风险时，红利防守仓在 `09:30 ~ 09:45` 往往因成长股高开吸血而出现资金分流假摔；此时**绝不可在早盘分流低点劝砍防守仓**，必须等待 `10:00` 后大盘高开回落、防御资金回流修复 VWAP 后再按均线得失客观评估。

## 三、 盘中每 5 分钟全市场高频差分雷达（09:30 ~ 15:00）

通过 [intraday_radar.py](./scripts/intraday_radar.py) 在 A 股交易时段（北京时间交易日 `09:25~11:35`、`12:55~15:05`，基于 `utils.trading_clock.cn_today`）每 5 分钟拉取一次全市场 `7,807` 只标的快照，并与上一份有效快照计算差分（`Δpct_5m`、`Δamt_5m`、`Δred_common_5m`）。

* **首次扫描与中途重启防误报保护（`_is_fresh_baseline`）**：仅当上一份快照属于当日且间隔 `<= 900 秒`（15 分钟，或处于 `11:20~11:36` 至 `12:55~13:12` 的午休跨段桥接窗口）时才计算 5 分钟差分；当日首次启动或中途停机超 15 分钟后重启时，仅重置基准快照并将差分置为 `0`，防止把数小时或全天涨跌幅误报为 5 分钟异动。
* **广度同池对齐与 90% 覆盖率闸门（`_compute_breadth_and_coverage`）**：
  * `Δred_5m` 严格只对比**当前帧与上一帧同时返回有效报价的共同 A 股集合（`common_syms`）**，防止把单帧漏返回的股票误算成“翻绿跳水”；
  * 若两帧共同有效 A 股数低于上一帧有效 A 股数的 **`90%`**，判定为**数据缺口（`coverage_ok = False`）**，自动跳过情绪骤变（`L2:breadth`）与高红盘率依赖信号，并在卡片顶部显式标注 `⚠️ 数据缺口：本帧只回来 N 只 A 股`。
  * 若 `000001.SH` 或 `399001.SZ` 任一指数缺失有效报价，不合并输出残缺成交额，卡片显式标注 `⚠️ 指数数据缺口`。
* **指数与个股严格隔离**：仅对沪深京 A 股（`.SH` 的 `60/68` 开头、`.SZ` 的 `00/30` 开头、`.BJ`）统计涨跌家数与匹配 `l2_map`，排除 `000001.SH`、`000300.SH`、`399001.SZ` 等指数干扰。

1. **持仓股 5 分钟贴身风控（冷却期内绝不降级误报）**：
   * **🔴 L4 破位止损（电话加急，无成交额门槛，防开盘跳空/一字跌停漏报）**：持仓股 `现价 <= 预设硬止损价` $\rightarrow$ 立即触发 `L4` 电话加急（按 `86400 秒` 全天冷却，每个交易日仅拨打一次电话，且冷却期内不向下穿透降级为 L3/L2）；
   * **🟠 L3 持仓急跌（短信加急）**：持仓股 5 分钟急跌 `Δpct_5m <= -2.0%` 且 `现价 < VWAP` $\rightarrow$ 触发 `L3` 短信加急；
   * **🟡 L2 做 T 高抛（应用内加急）**：持仓股偏离 VWAP `vwap_dev > +3.0%` $\rightarrow$ 触发 `L2` 应用内加急。
   * **持仓行情回补与缺口告警**：全市场 `universes` 快照若漏掉持仓代码，`run_once` 会按 `--holding` 列表再拉一次个股报价；若仍无有效报价，卡片置顶 `持仓行情缺口` 并以 `L2` 加急提示（禁止静默跳过止损监控）。
2. **威科夫核心池信号与市场共振监控（保留 L4 电话 / L3 短信加急 + 同步写入留档日志）**：
   * **🔴 L4 满级起跳板突破（电话加急）**：
     * 命中与当日 `review_trace_YYYYMMDD.json.gz` 同日期的 `recommendation_tracking_YYYYMMDD.json` 的 `springboard_combo == "A+B+C"`（严格过滤旧日期推荐文件；备份里 `code` 常为整型如 `2594`，读入时规范成 6 位 `002594` 对齐 trace），或 `review_trace` 内的 `entry.entry_type == "launchpad"` / `"启动平台"`（**不要求** `l2_eligible` 或 `upper_wick_pct <= 2.0%`；L3 地量点火才要求该过滤）；
     * 覆盖率正常（`coverage_ok = True`）且全市场红盘率 `> 80%`，5 分钟涨速 `Δpct_5m >= +2.5%`，总涨幅 `+2.8% ~ +6.0%`，`0% <= vwap_dev <= 2.0%`，5 分钟新增成交额 `Δamt_5m >= 0.30亿`。
   * **🟠 L3 威科夫 `L2+L3 地量 / 吸筹` 5 分钟点火与稳健中军加速确认（短信加急，严禁高位妖股触发）**：
     * 同时满足 `l2_eligible = True` 且 `l3_eligible = True`（或 `stage == "候选池已捕获"`），`l2_channel` 含 `地量` 或 `吸筹`（排除纯 `点火破局` 高位股），且 `RPS <= 80.0`、日内振幅 `amp_pct <= 6.5%`、开盘涨跌幅 `open_pct >= -2.0%`；
     * 当前总涨幅处于 **`+2.8% ~ +5.0%`** 区间，现价在 VWAP 上方且乖离率 `0% <= vwap_dev <= 2.0%`，上影线幅度 `upper_wick_pct <= 2.0%`；
     * **双通道触发（兼顾标准点火与机构推土机式慢涨）**：
       * ① **标准 5m 点火**：`Δpct_5m >= +1.8%`、`Δamt_5m >= 0.30亿` 且累计成交 `>= 1.0亿`；
       * ② **`10:30` 后稳健中军加速确认（`🎯稳健中军加速`）**：经过早盘 1 小时换手检验后（`>= 10:30`），处于黄金甜点区（`24 <= RPS <= 68`）、无长上影（`upper_wick_pct <= 1.0%`）、低振幅（`amp_pct <= 5.5%`）、高流动性（累计成交 `>= 1.8亿`）的机构中军，只需 `Δpct_5m >= +1.2%` 且 `Δamt_5m >= 0.25亿` 即可触发 `L3` 主升确认提醒，防止踏空“每 5 分钟涨 `1%` 稳步推升”的机构趋势股。
   * **👀 全市场 `L2+L3` 稳健中军盘中观察池（`summarize_zero_bias_l2_leaders`，盘中辅助观察参考，只看稳健中军、不追妖股）**：
     * 每次扫描全市场 A 股（非 ST 的 `60/68/00/30` 标的），按固定盘中观察条件筛选同时满足：`l2_eligible and l3_eligible`、含 `地量` 或 `吸筹` 通道、`12 <= RPS <= 80`（`24 ~ 68` 区间优先，剔除 `RPS > 80` 高位妖股）、所属行业红盘率 `>= 75%`、涨幅 `+1.5% ~ +5.0%`（不追 `>5%` 半山腰且跑赢行业均值 `75%`）、成交额 `>= 1.5亿`、日内振幅 `<= 6.5%`、现价站稳 VWAP 上方（`+0.1% ~ +2.2%`）、实体红 K（`last >= open`）且上影线 `<= 1.2%`。
     * 在 `6. 全市场 A 股 5m 异动榜` 中，对非 `L2`、`RPS > 80`、涨幅 `> 5.0%` 或巨震标的显式标注 **`[⚠️妖股/高位勿追]`**，与 **`[🟢L2稳健]`** 严格隔离。
   * **🟡 L2 行业共振自动挂载同板块 `L2` 稳健中军（严格去重防轰炸）**：
     * ① 持仓股偏离 VWAP `> +3.0%`；② 同一行业内同时有 `>= 3` 只 A 股出现 `Δpct_5m >= +2.5%` 且 `Δamt_5m >= 0.30亿` 时，自动在该条 `L2` 共振告警末尾挂载 **`👉 🎯同板块L2稳健中军`**（该板块内当前处于 `+1.5% ~ +4.8%` 且站稳均线的 `L2+L3 地量/吸筹` 中军），让板块异动直接转化为可落地的稳健中军买点；③ 覆盖率 `>= 90%` 下共同股票池红盘家数 5 分钟变化 `|Δred_common_5m| >= 400 家`。
   * **📁 盘中提醒留档与离线统计（`~/.wyckoff/radar_alerts.jsonl`）**：
     * 所有触发的 `L2/L3/L4` 告警信号均自动追加写入仓库外的 `~/.wyckoff/radar_alerts.jsonl`（记录日期、时刻、现价、VWAP 乖离率、5m 涨速、成交额），供后续按可成交价统计扣除双边交易成本后的远期超额收益。

## 四、 飞书四级加急通知矩阵与加急焦点置顶规范（普通 / App / 短信 / 电话）

卡片发送与加急请求统一通过 `lark-cli --as bot` 以同一机器人身份调用，**仅当卡片与所需加急均成功时才将冷却时间戳写入状态文件**（卡片成功但 `urgent_phone`/`urgent_sms`/`urgent_app` 失败视为投递未完成，不锁冷却；若已尝试发送但失败，行情差分基线 `quotes`/`ts` 也保持上一份成功快照不动，避免 `Δpct_5m`/`Δamt_5m` 被归零后无法重试；`--dry-run` 不写共享状态文件）。持仓止损与起跳板突破、持仓急跌与威科夫点火使用**分种类冷却键**（如 `L4:holding_stop:{sym}` vs `L4:springboard:{sym}`），避免起跳板电话耗尽同标的全日止损电话配额。守护进程 `--daemon` 连续 3 次扫描异常时自动推送一条 `L1` 故障告警卡片。

* **🚨 加急焦点一目了然（`_build_urgent_focus_banner`）**：凡触发 `L2 / L3 / L4` 加急通知的卡片，标题强制改写为 `【L2/L3/L4 加急焦点】HH:MM <第一触发焦点>`，并在卡片正文最顶部置顶渲染 **`🚨 【本次 L2/L3/L4 加急核心焦点 — 为什么给你发加急】`** 与 **`💡 关注重点`**，确保用户在手机锁屏弹窗或打开卡片第一眼即可明确核心异动标的与操作应对方向。

## 五、 验钞纪律与盘面观察准则

1. **两市成交额与国家队 20 大 ETF 分时曲线存档及同时刻对比（`~/.wyckoff/intraday_turnover/`）**：
   * 严禁拿单只 ETF 成交额冒充全市场量比，也**严禁在盘中拿当前两市成交额直接与“昨日全天成交额”硬比**（会导致盘中尤其下午量比系统性失真）。
   * 雷达每次扫描自动将 `(HH:MM, 成交额)` 追加至 `turnover_YYYYMMDD.jsonl` 与 `nt_etf_YYYYMMDD.jsonl`（午休 `11:31~12:58` 或收盘后 `>15:00` 运行时自动对齐至 `"11:30"` 或 `"15:00"` 交易终局时刻）：
     * 从第二个交易日起，自动与上一交易日**同一时刻（`±10 分钟`）**的成交额对比；
     * `13:00` 之后自动用当前两市成交额减去当日上午收盘成交额，汇报 **`13:00 至今` 午后增量成交额**；
     * **国家队 20 大重点 ETF 盘口定性**：领头 ETF 同时展示成交额、涨跌幅与分时均线状态（`🟢` 均线上 / `🔴` 水下），据此区分**“全面放量护盘”**、**“托而不举横盘控温”**与**“压大放小（压制沪深300/上证50权重、放行双创与中证1000）”**。
2. **跨境资金电报（南向/汇率）反身性判读**：
   * 港股通**南向资金早盘净卖出**（如 `>= 20亿港元`）在指数高开日通常代表内资机构对隔夜高开科技股的获利了结，与 A 股 `09:30 ~ 10:30` 高开回落同源；只要离岸人民币汇率（USD/CNH）未出现急贬跳水，即定性为“高开分歧换手”而非系统性风险。
3. **评估个股时同时报出核心验钞指标**：
   * 快照雷达报出：`现价 (涨跌幅)` | `持仓成本与浮盈亏%` | `分时均价 VWAP (🟢均线上/🔴水下 乖离率%)` | `5分钟涨速与5分钟新增成交额` | `威科夫 L2/L3 通道与 RPS`。
4. **禁止因情绪迎合而改变客观标准**：
   * 坚持分时均价线（VWAP）与量能确认，不在均线下方盲目接飞刀，也不在远离均线（`vwap_dev > 3%`）时高位追涨。
5. **超跌首阳次日（`T+1`）盘面观察参考（经验观察，非自动执行指令）**：
   * 经验观察表明，当指数在均线空头排列（`C < MA20 < MA50`）下出现单日大幅超跌反弹后，次日（`T+1`）早盘常出现获利盘换手分歧，不宜在早盘集合竞价大幅高开时盲目追高；
   * 盘中重点观察指数与领涨主线在分时均价线（VWAP）附近的承接力度：若单边放量跌破分时均线且持续走弱，需防范“一日游”回落风险；若缩量回踩均线企稳并放量转强，再结合盘中硬指标评估右侧机会。
6. **尾盘独立选股与盘中雷达严格解耦**：
   * **尾盘或盘后独立选股时，严禁拿盘中雷达触发过的候选股作为起点**（拿同一份盘中异动信号当选股起点等于自我验证）；尾盘/盘后选股必须独立从全市场日线漏斗与客观因子出发。
7. **🔄 去弱留强与腾笼换鸟时序衔接纪律**：
   * 对于昨日买入的 `T+1` 弹性持仓，若早盘冲高（如 `+4% ~ +6%`）后回落跌破分时均价线（VWAP）且 `15 分钟` 内无法收复，应果断在上午锁利止盈（避免拖延至尾盘 `14:20`），从而在 **`10:30 ~ 13:30` 黄金窗口**内释放可用现金，无缝切入当日已经过 1 小时换手验钞的 `L2+L3` 稳健中军。
8. **🚫 每日盘后归零原则（严禁主观预设次日剧本）**：
   * 盘后复盘仅总结当日已发生的客观得失与系统机制迭代，**严禁在盘后主观预设“某只今日踏空的股票明天一定还能买/还会涨”**；任何标的次日是否具备操作价值，100% 取决于次日 `08:35` 盘前反身性校验与 `09:30 ~ 10:30` 的实际开盘位置、分时均线承接及板块资金共振。

## 六、 生产 Trace 同步与本地 `lark-cli` 执行命令

1. **生产 `review_trace` 自动与手动同步（`~/.wyckoff/traces`）**：
   * 脚本在未指定 `--trace` 时默认按 `~/.wyckoff/traces`、`/tmp`、`data/` 顺序查找最新 `review_trace_*.json.gz`，并在缺失或过期时自动通过 `gh run download` 从 GitHub Actions `wyckoff_funnel.yml` 下载最新 `daily-job-artifacts-*` 到 `~/.wyckoff/traces`。
   * 如需在盘前手动预拉取最新生产 Trace，可执行：

```bash
mkdir -p ~/.wyckoff/traces && gh run download $(gh run list --workflow wyckoff_funnel.yml --status success -L 1 --json databaseId --jq '.[0].databaseId') -p "daily-job-artifacts-*" -D ~/.wyckoff/traces
```

2. **本地 `lark-cli` 调用说明**：
   * 脚本直接调用本机已登录的 `lark-cli`（通过 `lark-cli auth status` 动态获取当前登录用户的 `identities.user.openId`，并以 `--as bot` 发送互动卡片与加急通知），**无需在代码仓库或磁盘配置文件中存储任何个人 `open_id` 或持仓信息**。如需在单次运行中附带持仓监控，可通过命令行参数 `--holding <代码:成本:止损>` 传入（`代码` 可为持仓账本六位码如 `600000`，或 TickFlow 后缀形式如 `600000.SH`；脚本会规范成行情键后再做止损匹配）：

```bash
# 单次运行全市场 7,807 标的差分扫描（自动同步 trace 并通过本机 lark-cli 发送）：
.venv/bin/python .agents/skills/intraday-radar/scripts/intraday_radar.py --once

# 盘中每 5 分钟守护扫描（自动对齐时钟周期、异常自愈、非交易时段休眠）：
.venv/bin/python .agents/skills/intraday-radar/scripts/intraday_radar.py --daemon --interval 300
```

3. **跨时区 Cron 星期映射注意（`PST UTC-8` vs `BJT UTC+8`）**：
   * 若在 `PST (UTC-8)` 环境下配置定时任务，北京时间周一至周五（`08:35 ~ 15:00 BJT`）对应美西时间**周日 `16:35` 至周四 `23:00`**，因此 Cron 的星期字段必须设为 `0-4`（而非 `1-5`，否则会漏掉北京时间周一并误在周六触发）。
